## Bucket 1 — memorySearch decision

**Trigger**: After PR-1 merges and v1.1.0 stable locally.

Reference: Option B from `docs/1.1.0-upgrade-suggestion.md` §六.

### Open questions

1. **SOUL.md ban granularity** — ✅ **Closed 2026-05-13 (Bundle A / Option 1b).** Decision doc: `docs/1.1.0-upgrade-evidence/bucket1-q1-q3-decision-options.md`. SOUL.md:32 rewritten to explicitly scope the ban to ERP business data and carve out operational-signal recall as future-allowed (gated on Q2/Q3 if/when re-opened).
2. **Higress `/v1/embeddings` route** — ✅ **Closed 2026-05-13 (Option 2a / Keep disabled).** No infra change. Re-open trigger: real product driver for operational memory appears (UX preference feature, repeated routing-heuristic re-derivation, or compliance airgap requirement).
3. **Memory file write strategy** — ✅ **Closed 2026-05-13 (gated on Q2, currently n/a).** If Q2 is re-opened, the recorded preference is operator-driven nightly writer (3a-ii) + every diff audited via audit-mcp (3c-ii) to preserve the L5 invariant.
4. **v1.1.0 default check** — ✅ **Closed 2026-05-13.** Evidence: `docs/1.1.0-upgrade-evidence/bucket1-memorysearch-default-check.log`. Summary:
   - v1.1.0 only injects `agents.defaults.memorySearch` when `HICLAW_EMBEDDING_MODEL` is non-empty (see `/opt/hiclaw/scripts/init/start-manager-agent.sh` `if $emb_model != ""` guard).
   - `/opt/hiclaw/scripts/lib/hiclaw-env.sh` uses **single-dash** `${HICLAW_EMBEDDING_MODEL-text-embedding-v4}`, so unset → broken default. Empty string in compose is **load-bearing** (kept, with sharpened comment).
   - The Python `pop('memorySearch')` block in `manager-init-internal.sh` is dead code when the empty string is set, and was removed on this branch.

### Decision matrix

| Scenario | SOUL ban | Runtime memorySearch | Higress embeddings route | Memory files |
|---|---|---|---|---|
| Status-quo (keep) | Full ban | Removed | None | None |
| **Bundle A — chosen 2026-05-13** | **Scoped to ERP business data; operational signals carved out for future re-enable** | **Removed** | **None** | **None** |
| Operational-only | Limit to "ERP business data" | Keep, point at real embedding | Add | Add + write strategy |
| Full unban (not recommended) | Drop ban | Keep | Add | Add |

**Final choice:** Bundle A. SOUL contract clarified, runtime memory stays disabled. Rationale: no concrete product driver for operational memory today; enabling it without audited writes contradicts L4/L5; clarifying SOUL contract is cheap and unblocks future re-enable. Full options matrix and reasoning in `docs/1.1.0-upgrade-evidence/bucket1-q1-q3-decision-options.md`.

**Branch**: `ralph/memorysearch-decision` (this branch). Bucket 1 closed.

## Bucket 2 — Split `hiclaw-embedded` into standalone services

**Trigger**: After PR-2 merges and v1.1.0 stable on ECS for ≥ 1 week.

### Scope

- Replace single `hiclaw-embedded` Deployment with 4 dedicated Deployments:
  - `tuwunel`
  - `minio`
  - `higress`
  - `element-web` (optional)
- Adopt `hiclaw-controller:v1.1.0` for the K8s controller component.
- Move bundled bootstrap out of `hiclaw-embedded` into:
  - `init-minio-job.yaml` (bucket creation, policy)
  - `init-higress-job.yaml` (LLM route registration — partly already extracted in PR-1)
  - Tuwunel `homeserver.yaml` ConfigMap mounted into Tuwunel Pod
  - Element Web `config.json` ConfigMap

### Why deferred

- Don't change two things at once: v1.1.0 upgrade and topology refactor are independent.
- v1.1.0 was released < 48 h before this work; embedded path is well-trodden, standalone path with `hiclaw-controller` is less battle-tested.
- DNS aliases (`aigw-local` / `matrix-local`) abstract topology — embedded today doesn't preclude split tomorrow.

### Pre-conditions

- v1.1.0 stable on ECS for ≥ 1 week (no new error patterns).
- `hiclaw-controller:v1.1.0` has visible community usage / GitHub feedback.
- Memory budget reconfirmed (split adds ~1–1.5 GB k3s sidecar / probe / runtime overhead).

**Branch when ready**: `ralph/split-embedded-standalone`.
