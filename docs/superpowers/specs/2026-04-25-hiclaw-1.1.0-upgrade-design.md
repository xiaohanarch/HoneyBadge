# HiClaw v1.0.9 → v1.1.0 Upgrade — Design Spec

- **Date**: 2026-04-25
- **Branch**: `ralph/1.1.0-upgrade`
- **Scope**: Option A — upgrade itself only. Option B (`memorySearch`) and Option C (Hermes / CRD migration / standalone split) deferred to `docs/1.1.0-upgrade-followups.md`.
- **Validation gate**: V2.5 — V2 (per-workaround evidence) + 1–2 hour soak run.
- **PR strategy**: P2 — two sequenced PRs. PR-1 = local docker-compose + workaround removal (this branch). PR-2 = K8s manifest split (off merged master, branch `ralph/1.1.0-upgrade-k8s`).
- **Deployment path**: Embedded (single `hiclaw-embedded` container bundles Tuwunel / MinIO / Higress / Element Web). Standalone split is a deferred follow-up.

## Source documents

- `docs/1.1.0-upgrade-suggestion.md` — original research (2026-04-24)
- HiClaw v1.1.0 release notes — <https://github.com/agentscope-ai/HiClaw/releases/tag/v1.1.0>

## §1 Architecture Change

### Before (v1.0.9)

```
docker-compose: [hiclaw-manager (all-in-one: Tuwunel+MinIO+Higress+Element+Manager-agent)]
                + 2× [hiclaw-worker]

K8s:           [manager.yaml monolith Deployment]
                + [workers.yaml]
```

### After (v1.1.0, embedded path)

```
docker-compose: [hiclaw-embedded (Tuwunel+MinIO+Higress+Element bundled)]
                + [hiclaw-manager (lightweight agent only, ~1.7 GB lighter)]
                + 2× [hiclaw-worker]

K8s:           [embedded.yaml Deployment] (replaces infra portion of old manager.yaml)
                + [manager.yaml lightweight Deployment]
                + [workers.yaml]
```

### Network model

DNS aliases unchanged for consumers:

- `aigw-local.hiclaw.io` and `matrix-local.hiclaw.io` now resolve to `hiclaw-embedded` (was `hiclaw-manager`).
  - In compose: aliases declared via `networks.<net>.aliases` on the `hiclaw-embedded` service.
  - In K8s: `Service` objects (`aigw-local`, `matrix-local`) updated to select Pods with `app=hiclaw-embedded` labels (was `app=hiclaw-manager`).
- Direct `hiclaw-manager:6167` / `:9000` / `:8080` / `:18001` / `:18888` references in compose retarget to `hiclaw-embedded:<same-port>`.
- Workers, MCP servers, frontend, server, auth: unchanged code paths because they all use the DNS aliases.

### ECS resource budget (4c / 16 GB)

| Component | Estimated RSS |
|---|---|
| `hiclaw-embedded` (bundled infra) | ~2–3 GB |
| `hiclaw-manager` (lightweight) | ~512 MB |
| 2× workers | ~1 GB total |
| HiClaw subtotal | **~4 GB** |
| NebulaGraph + Milvus + Postgres + Redis + frontend + server + auth + 3 MCPs | ~8 GB |
| k3s + OS buffer | ~1–1.5 GB |
| **Cluster total** | **~13–14 GB** |
| **Headroom** | **~2–3 GB** |

### Zero business-code changes

Matrix DM, MCP SSE, `openclaw.json` schema, Contract 002, dispatch scripts (`dispatch.sh` / `fast-query.sh`), MCP servers, `src/honeybadge/llm/adapter.py` — all protocol-stable.

## §3 Validation Procedure (V2.5)

### Stage A — Local docker-compose (PR-1)

#### A.0 Baseline (capture v1.0.9 evidence)

On current `master`, before any code changes:

1. `docker compose up -d` clean.
2. Confirm dispatch round-trip works (existing E2E `tests/e2e/test_02_chat.py` green) — establishes "v1.0.9 with all current workarounds works".
3. For each of the 6 workarounds: temporarily comment out the workaround, capture the failure mode, restore the workaround. Save logs as `docs/1.1.0-upgrade-evidence/v109-bug-<N>.log`.

#### A.1 Switch to v1.1.0 (workarounds still in place)

1. Apply PR-1 file changes (Dockerfile bumps, compose split, init script edits, retargets) — but **do not delete workarounds yet**.
2. `docker compose down -v` then `docker compose up -d`.
3. Verify all containers healthy: `hiclaw-embedded` → Tuwunel / MinIO / Higress / Element Web internal supervisord all running; `hiclaw-manager` → openclaw lightweight agent running; 2 workers up.
4. Run existing E2E `tests/e2e/test_02_chat.py` → must be green.

#### A.2 Workaround-by-workaround removal (V2 core)

For each of the 6 workarounds, in the order listed in §2:

1. Delete the workaround from the script.
2. Recreate the affected container(s): `docker compose up -d --force-recreate hiclaw-manager` (or `hiclaw-embedded` for Higress-related changes).
3. Re-run the v1.0.9 reproduction scenario from A.0.
4. **Pass criterion**: scenario succeeds without the workaround.
5. **Fail criterion**: scenario reproduces v1.0.9 failure mode → workaround stays, document in followups doc.
6. Save evidence log: `docs/1.1.0-upgrade-evidence/v110-fix-<N>.log`.

#### A.3 Soak run (≥ 90 min)

1. With all confirmed-fixed workarounds removed, leave the stack running 90 min minimum.
2. Drive periodic load: pytest loop firing one `test_02_chat.py`-style query every 5 min (cadence that exposed v1.0.9 token-rotation bug).
3. **Pass criterion**: zero `ERROR` log entries from `hiclaw-manager` / `hiclaw-embedded` Tuwunel-controller / Higress; no `403` / `401` from Higress AI gateway; no Matrix `M_UNKNOWN_TOKEN` errors; queries succeed end-to-end throughout.
4. Capture `docker compose logs --since 90m` snapshot to `docs/1.1.0-upgrade-evidence/soak-local.log`.

#### A.4 PR-1 merge gate

- [ ] All 6 workarounds either deleted-with-evidence or kept-with-followup-issue documented.
- [ ] E2E `test_02_chat.py` green pre-soak and post-soak.
- [ ] Soak run clean for ≥ 90 min.
- [ ] `MEMORY.md` / `CLAUDE.md` / `README.md` updated.
- [ ] `docs/1.1.0-upgrade-followups.md` exists and lists Option B / C + standalone-split.
- [ ] `v1.0.9-stable` tag pushed to remote on `master` before merge.

### Stage B — K8s on ECS (PR-2)

#### B.0 Baseline

SSH to ECS, confirm v1.0.9 K8s deployment still healthy. `kubectl get pods -n honeybadge` — all Running. Existing E2E via SSH tunnel green.

#### B.1 Apply PR-2 manifests

1. New branch `ralph/1.1.0-upgrade-k8s` off merged master.
2. `kubectl apply -k deploy/k8s/` with new `embedded.yaml` + slimmed `manager.yaml`.
3. Wait for `hiclaw-embedded` Pod Ready (will take longer than current manager — bigger volume mount + 4 services in supervisord).
4. Confirm Pods: `hiclaw-embedded`, `hiclaw-manager`, `hiclaw-worker-*` × 2 all Running.

#### B.2 E2E via SSH tunnel

Per `MEMORY.md` standard procedure:

1. `kubectl port-forward` for frontend / server / auth on ECS.
2. SSH tunnel locally.
3. `pytest tests/e2e/test_02_chat.py -v --timeout=180` → must be green.

#### B.3 Memory budget verification

1. `kubectl top pod -n honeybadge` after 30 min stable.
2. **Pass criterion**: total node memory < 14 GB (leave 2 GB buffer); no Pod OOMKilled.
3. Capture snapshot to `docs/1.1.0-upgrade-evidence/ecs-memory.log`.

#### B.4 Soak run on ECS (≥ 90 min)

Same protocol as A.3 but against ECS via SSH tunnel. Save to `docs/1.1.0-upgrade-evidence/soak-ecs.log`.

#### B.5 PR-2 merge gate

- [ ] All Pods Running, no restarts, no OOMKills.
- [ ] E2E green via SSH tunnel.
- [ ] Memory budget under 14 GB sustained.
- [ ] Soak run clean ≥ 90 min on ECS.
- [ ] Rollback rehearsal: `kubectl apply -k deploy/k8s/` from `v1.0.9-stable` tag in a sandbox namespace succeeds.

### Evidence directory policy

`docs/1.1.0-upgrade-evidence/` is **committed** to the repo:

- Whole point of V2.5 is evidence-based decisions; evidence not in repo doesn't survive review cycles.
- ~5–10 MB total — rounding error against existing repo.
- Each log truncated to ~100 relevant lines + `### context` header for readability.

## §4 Risk & Rollback

### Top risks

| # | Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|---|
| 1 | v1.1.0 has unknown bugs (released < 48 h before this work) | Medium | High | V2.5 90-min soak forces real traffic; PR-1 stays local until clean |
| 2 | `workers-registry.json` → CRD auto-migration corrupts existing registrations | Medium | High | Local PR-1 catches before ECS; back up `workers-registry.json` from MinIO before first v1.1.0 boot; document restore |
| 3 | A workaround is *not* actually fixed in v1.1.0 (release notes vs reality drift) | Medium | Low–Medium | A.2 per-workaround verification; bugs not fixed go to followups doc, workaround stays |
| 4 | `hiclaw-embedded` Pod startup ordering (Higress before MinIO before Tuwunel) | Medium | Medium | All four services run inside same Pod via supervisord — internal ordering is upstream's concern; only init-workers Job needs proper `depends_on` |
| 5 | ECS memory overrun when old + new HiClaw briefly coexist during rolling update | Low | Medium | Use `Recreate` strategy on `hiclaw-embedded` Deployment (not RollingUpdate) — new Pod waits for old to terminate |
| 6 | DNS alias (`aigw-local` / `matrix-local`) retarget fails, services briefly unresolvable during PR-2 cutover | Low | High (full outage) | Aliases are Service objects with stable selectors that match `hiclaw-embedded` Pod labels — DNS continues resolving once labels match |
| 7 | Soak run on local catches a bug that doesn't reproduce on ECS (different OS, memory pressure) | Medium | Medium | Stage B repeats full soak on ECS — local soak is a filter, not a substitute |

### Rollback procedure

#### Pre-merge gate (must complete before PR-1 merge)

```bash
git tag -a v1.0.9-stable -m "Last v1.0.9 release before HiClaw v1.1.0 upgrade"
git push origin v1.0.9-stable
```

#### PR-1 rollback (local docker-compose)

```bash
git checkout v1.0.9-stable -- deploy/docker/docker-compose.yaml deploy/hiclaw/
docker compose down -v
docker compose up -d
bash deploy/hiclaw/init-workers.sh
```

Recovery time: ~5 min. No data loss (HiClaw state in MinIO bucket, volume-backed).

#### PR-2 rollback (ECS K8s)

```bash
ssh ecs
cd /path/to/repo && git checkout v1.0.9-stable
kubectl apply -k deploy/k8s/
kubectl rollout status deployment/hiclaw-manager -n honeybadge --timeout=300s

# embedded Deployment is new in PR-2; kubectl apply won't remove it
kubectl delete deployment hiclaw-embedded -n honeybadge

# PVC retention: keep on rollback (allows clean re-attempt without re-bootstrapping MinIO)
# Only delete PVC if explicitly wiping for fresh start:
# kubectl delete pvc hiclaw-embedded-data -n honeybadge
```

Recovery time: ~3–5 min.

### Disaster scenarios

| Scenario | Detection | Response |
|---|---|---|
| `hiclaw-embedded` won't start | Pod CrashLoopBackOff within 5 min | `kubectl logs` for which sub-service failed; if upstream image bug, rollback to `v1.0.9-stable` and file issue against HiClaw repo |
| Auto-migration corrupts worker registry | Workers fail to start; `workers-registry` empty in MinIO console | Restore backup `workers-registry.json` to MinIO; rerun `init-workers.sh`; rollback if persistent |
| Soak run fails 30 min in | New ERROR pattern in `hiclaw-manager` logs | Capture log snapshot, decide: minor (file followup, keep PR open) vs major (rollback the offending workaround deletion only, not whole upgrade) |
| Memory exceeds 14 GB on ECS | `kubectl top` or node OOM events | Scale workers from 2 → 1 temporarily; rollback if persistent — investigate which sub-service is leaking |

## §5 Deferred Items / Followups

This section defines the contents of `docs/1.1.0-upgrade-followups.md`, created in PR-1 and updated as PR-1 / PR-2 close.

### Bucket 1 — `memorySearch` decision (Option B from `docs/1.1.0-upgrade-suggestion.md` §六)

**Trigger**: After PR-1 merges and v1.1.0 stable locally.

**Open questions:**

1. **SOUL.md ban granularity**: Current Manager SOUL.md bans `memorySearch` entirely *for ERP data*. Decide whether to relax to allow operational-memory recall (e.g., "user prefers Chinese tabular output", "dispatch rule X triggered N times in 90d") while keeping ERP ban. Affects `hiclaw/manager/agent/SOUL.md` line 32.
2. **Higress `/v1/embeddings` route**: If allowing operational memory, pick embedding backend — DashScope `text-embedding-v4`, MiniMax `embo-01`, or self-hosted Ollama `bge-m3`. Affects `init-workers.sh` Step 3c (add second route) and `.env` (new API key).
3. **Memory file write strategy**: If `memorySearch` enabled, define who writes `MEMORY.md` / `memory/YYYY-MM-DD.md` (Manager autonomous via `memoryFlush` vs offline operator-driven), what gets written, whether memory file changes feed L5 PostgreSQL audit log.
4. **v1.1.0 default check**: First action of this followup branch is verifying whether `hiclaw-manager:v1.1.0` still injects `memorySearch` defaults into `openclaw.json`. If not, the `manager-init-internal.sh` `pop('memorySearch')` line can simply be deleted.

**Decision matrix (record final choice in followup doc):**

| Scenario | SOUL ban | Runtime memorySearch | Higress embeddings route | Memory files |
|---|---|---|---|---|
| Status-quo (keep) | Full ban | Removed | None | None |
| Operational-only (recommended target) | Limit to "ERP business data" | Keep, point at real embedding | Add | Add + write strategy |
| Full unban (not recommended) | Drop ban | Keep | Add | Add |

**Branch when ready**: `ralph/memorysearch-decision`.

### Bucket 2 — Split `hiclaw-embedded` into standalone services

**Trigger**: After PR-2 merges and v1.1.0 stable on ECS for ≥ 1 week.

**Scope:**

- Replace single `hiclaw-embedded` Deployment with 4 dedicated Deployments: `tuwunel`, `minio`, `higress`, `element-web` (Element optional).
- Adopt `hiclaw-controller:v1.1.0` for the K8s controller component.
- Move bundled bootstrap out of `hiclaw-embedded` into:
  - `init-minio-job.yaml` (bucket creation, policy)
  - `init-higress-job.yaml` (LLM route registration — partly already extracted in PR-1)
  - Tuwunel `homeserver.yaml` ConfigMap mounted into Tuwunel Pod
  - Element Web `config.json` ConfigMap

**Why deferred:**

- Don't change two things at once: v1.1.0 upgrade and topology refactor are independent.
- v1.1.0 was released < 48 h before this work; embedded path is well-trodden, standalone path with `hiclaw-controller` is less battle-tested.
- DNS aliases (`aigw-local` / `matrix-local`) abstract topology — embedded today doesn't preclude split tomorrow.

**Pre-conditions:**

- v1.1.0 stable on ECS for ≥ 1 week (no new error patterns).
- `hiclaw-controller:v1.1.0` has visible community usage / GitHub feedback.
- Memory budget reconfirmed (split adds ~1–1.5 GB k3s sidecar / probe / runtime overhead).

**Branch when ready**: `ralph/split-embedded-standalone`.

### Bucket 3 — Phase 3 optimizations (Option C)

**Trigger**: After Buckets 1 & 2 land, or as needed for Phase 1 roadmap.

**Items:**

1. **CRD declarative migration** — migrate worker bootstrap from imperative `init-workers.sh` (bash + MinIO push) to declarative `Worker` CRDs (`wk` resource). Eliminates init-workers Job entirely. Branch: `ralph/crd-declarative-workers`.
2. **Hermes runtime evaluation for `analytics-worker`** — multi-step-analysis fits Hermes' autonomous coding-agent shape. Spike: implement one analytics task in Hermes vs current `agent` runtime; compare latency, cost, quality. Branch: `ralph/hermes-analytics-worker-spike`.
3. **Idle worker auto-stop** — `spec.state: stopped` to scale workers to 0 off-hours. Requires understanding warm-up cost. Low priority unless ECS cost becomes a concern.
4. **Adopt official Helm chart** — once v1.1.0 has stable upstream chart with HoneyBadge-overridable values, evaluate replacing kustomize manifests. Predicate on chart maturity (likely v1.2.0+ horizon).

### Bucket 4 — Workarounds v1.1.0 did not eliminate

**Trigger**: Created only if A.2 reveals one or more workarounds whose v1.0.9 failure mode still reproduces under v1.1.0.

**Per-item structure**: workaround location, original v1.0.9 bug description, A.2 reproduction log link, upstream issue link (filed by us), suggested re-attempt timeline (e.g., next HiClaw release).

**Branch when ready**: per-issue, e.g. `ralph/v110-fix-workaround-3-followup`.
