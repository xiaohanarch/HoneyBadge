## What did not work

### TC-005 logout — different failure mode, still fails

PR #111 changed `.click(force=True)` → `.hover()` on the user avatar, hypothesizing
that `<el-dropdown>` defaults to `trigger="hover"`. Failure went from
`AssertionError` (baseline) → `TimeoutError: Locator.wait_for: Timeout 5000ms exceeded`
(this run). Hover did not reveal the dropdown.

**Hypothesis revision:** Element Plus `<el-dropdown>` in this codebase may actually
default to `click`, or the teleported menu needs a stable hover hold longer than
Playwright's instant `hover()` provides. Need to investigate `el-dropdown` defaults
in the installed Element Plus version before next attempt.

### TC-205 session persistence — backend regression

PR #111 changed `wait_for_load_state("networkidle")` → `"domcontentloaded"`. Test
now reaches `wait_for_chat_ready()` but that helper times out at 20s waiting on
the Pinia chat store function. **This is a backend issue, not a test issue** —
the chat shell isn't reaching `connected=true` state on the reloaded page.

### TC-603 cache MCP — different failure mode

PR #111 added `kubectl port-forward -n honeybadge svc/redis 6379:6379`. Port-forward
now works (no more `ConnectionRefused`), but Redis rejects the test's hardcoded
`redis123` password:

```
Failed: Redis health check failed: invalid username-password pair or user is disabled.
```

The cluster's actual `REDIS_PASSWORD` differs from what `deploy/k8s/secrets.yaml:25`
declares. Cluster secret was rotated outside of git, or never matched the manifest.
Requires cluster-side inspection to resolve (`kubectl get secret -n honeybadge redis -o yaml`).

### TC-608 multi-MCP sequence — likely backend cascade

Test now uses `assert count() >= 3` (PR #111). Failed with TimeoutError on the chat
readiness — backend not producing 3 sequential responses. Same cascade as TC-205.
