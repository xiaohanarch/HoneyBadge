### `tests/e2e/test_01_auth.py` — RESOLVED (0 skips)

TC-005 fixed via three coordinated changes:
- Frontend: `ChatView.vue` user-avatar `<el-dropdown>` given `trigger="click"`
  (was default `hover`, inconsistent with the session dropdown on the same view
  which already used `trigger="click"`).
- Selector: `LOGOUT_ITEM` corrected from `.el-dropdown-item` to
  `.el-dropdown-menu__item` — Element Plus v2.9 renders dropdown items as
  `<li class="el-dropdown-menu__item">`, not `.el-dropdown-item`. The old selector
  matched zero elements in the DOM.
- Test: `.hover()` → `.click()`.

### `tests/e2e/test_02_chat.py` — RESOLVED (0 skips)

TC-110/111 deadlock resolved without an async-API migration:
- TC-110: `@pytest.mark.timeout(600)` gives 600s headroom for 3 queries × ~60s
  (~180s with a fresh Manager), so pytest-timeout never fires mid-query and the
  thread-kill deadlock is avoided. `reset_manager` prevents the glm-5.2 repetition
  loop (5-10 accumulated turns) from stalling Stage-1.
- TC-111: removed the Windows-only `skipif` — the deadlock concern only applies
  when pytest-timeout interrupts a long-running multi-query test. A single ~60-90s
  query is well within the 600s safety timeout.

### `tests/e2e/test_03_session.py` — RESOLVED (0 skips)

TC-205 resolved via Option A (Matrix history restore) instead of building a
backend POST write path (Option B was rejected as a double-write — Matrix already
persists messages server-side in Tuwunel). Changes:
- `useMatrixChat.ts`: added module-level `matrixEventToChatMessage` pure function
  that converts a `MatrixEvent` to a `ChatMessage | null` (handles contracts
  001/002/003 + plain Manager text; skips worker progress updates). Unlike
  `handleRoomEvent`, it does NOT apply the live-event filters
  (`toStartOfTimeline`, own-sender, `queryStartTime`) — history wants all
  messages.
- `useMatrixChat.ts`: added `waitForMatrixSync` helper (mirrors the sync wait in
  `findOrCreateManagerDmRoom`). The `preProvisionedRoomId` path in `initMatrix`
  calls `startClient` but does NOT await sync PREPARED.
- `useMatrixChat.ts`: rewrote `loadMessages` to read the DM room timeline via
  `scrollback(room, 50)` + iterate `room.timeline` instead of GETting
  `/api/sessions/{id}/messages`.
- `ChatView.vue`: reordered `onMounted` so `connect()` runs before
  `loadMessages()` (Matrix client must be initialized + synced before reading
  `room.timeline`).

### `tests/e2e/test_04_isolation.py` — RESOLVED (0 skips)

TC-305 rewritten to use `create_user_page` (separate browser contexts per user)
instead of single `page` + `localStorage.clear()` in-place user switching. The
assertion checks `localStorage.token` (per-user roles_jwt) — the originally-planned
`auth_store` key does not exist (Pinia auth store is in-memory only, no persist
plugin; auth data is written as individual keys by `useAuth.ts`).

### `tests/e2e/test_05_permissions.py` — RESOLVED (0 skips)

TC-407 resolved by adding REST API-level role enforcement (the backend previously
had none — L3 permissions lived only in the Cypher/worker path). Changes:
- `dependencies.py`: added `require_admin` dependency that checks the JWT
  payload's `roles` list for `"admin"`, returning 403 if authenticated but
  non-admin (401 still comes from `get_current_user` for missing/invalid tokens).
- `admin.py` (new router): `GET /api/admin/users` endpoint returning
  `DEMO_USERS` minus `password_hash`, guarded by `require_admin`.
- `app.py`: mounted the admin router.
- `test_05_permissions.py`: removed `@pytest.mark.skip`; fixed a latent
  vacuous-pass bug — the old test looked for `access_token`/`roles_jwt` in the
  login response but the endpoint returns `token`, so the assertion never ran.
  Now asserts login==200, token present, and `/api/admin/users`==403 for analyst.
